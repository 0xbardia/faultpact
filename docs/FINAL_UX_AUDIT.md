# FaultPact Final UX Audit

Audit date: 2026-09-23. Tested the live product from its public homepage in Chromium, then followed the public explorer, Pact, Provider, Coverage, Incident, Claim, docs, and purchase routes. Wallet-required actions were not signed.

## User confusion log

| Page | User goal | Confusing behavior | Root cause | Fix | Regression verification |
| --- | --- | --- | --- | --- | --- |
| `/` | Understand FaultPact quickly | The hero said “LIVE SYSTEM” and showed fixed availability, latency, hash, and facts as if they were current measurements. | Decorative values were hardcoded into the landing component and animated continuously. | Replaced them with a static Pact lifecycle that explains bonded capital → monitoring → evidence → GenLayer facts → contract evaluation. Rewrote the first paragraph to define Pacts, Coverage, and Provider-backed Claims. | Production build and real browser review at desktop and mobile sizes; no fictional measurements remain in the hero. |
| `/pacts/[id]` | Decide whether a Pact is suitable | Disabled SLA clauses appeared as `0%`; annual premium, deductible, payout cap, claim window, duration, scope, and capacity were hard to interpret. Provider and Service were missing. | The detail view omitted terms, rendered basis points as raw integers, truncated GEN fractions, and the indexer read region scope from the wrong level. | Show only applicable clauses, display all purchase and settlement terms in readable units, include Provider and Service, and retain scope from nested Pact terms. | Formatter and indexer regression tests; production build; Pact page rechecked against indexed record data. |
| `/pacts/[id]` | Compare bonded capacity and continue to purchase | Small exact GEN balances overflowed capital metrics, and the fixed Coverage action could cover the freshness label. | Three large metric values shared a narrow side panel and the CTA was fixed to the viewport. | Stack compact capital values and move the Coverage action into the Pact header beside navigation. | `PACT_SMALL_GEN_CAPITAL_FITS_DESKTOP_AND_MOBILE`; live Pact screenshot review. |
| `/app/purchase?pact=…` | Review Coverage before signing | An unknown requested Pact silently selected the first Pact, creating a risk of signing for the wrong product. Limits used raw wei even though the form looked like a customer amount field. | A fallback selected `pacts[0]`; the input used integer strings without GEN conversion. | The selected ID now loads directly and errors when unavailable. Amount input accepts GEN decimals and converts exactly with `BigInt`; the page shows Provider, Service, bounds, premium, and current capacity before review. | `INVALID_PACT_SELECTION_DOES_NOT_FALL_BACK`; exact GEN parser/formatter tests; purchase E2E review. |
| `/app/claims/[id]` | Understand how to file a Claim | A stored Claim was presented as a filing screen, but its review button had no transaction attached and could only reconnect the wallet. | A generic action review was reused for an existing Claim record. | The route now shows the Claim receipt and links to its Coverage and Incident. Claim filing is explicitly identified as unavailable in the web UI. | Manual route review; provider/claim write gap recorded as a release blocker. |
| `/incidents` | See when an Incident was observed | The list exposed raw Unix seconds instead of dates. | The table rendered chain seconds as plain text. | Format observation times as readable dates. | `INCIDENT_LIST_FORMATS_UNIX_TIMESTAMPS` plus live route review. |
| `/incidents/[id]` | Inspect evidence and follow settlement | External Evidence appeared fetched, hash-valid, and schema-valid even when the source returned 503 or its bytes did not match. Related Claims were also missing from the Incident page. | The indexer inferred verification from an onchain `usable` field that does not exist in the frozen Evidence record; the page had no Claim query. | Store checks as `NOT_CHECKED`, show the submitted hash and safe source link, distinguish onchain provenance from source verification, and link Claims filtered by Incident. | `INDEXER_DOES_NOT_CLAIM_EXTERNAL_EVIDENCE_WAS_VERIFIED`, `INCIDENT_SHOWS_RELATED_CLAIM_SETTLEMENT`; live Incident review. |
| `/provider`, `/provider/pacts`, `/provider/capital` | Register, publish a Pact, and manage capital | The console implied registration, publishing, deposit, allocation, and withdrawal were ready, but the screens contained review placeholders without transaction arguments. | Provider routes were explanatory stubs; only Coverage purchase passes a real write transaction. | Removed placeholder wallet actions and labeled the console read-only. Linked users to actual public Provider and Pact records. | Manual route review; the missing Provider write workflows remain a release blocker. |
| `/api/v1/ready` and indexed lists | Tell whether current data is safe to rely on | Readiness could stay healthy after the indexer stopped, and list responses reported request time as index time. | Readiness checked only cursor status; list metadata used `new Date()` instead of the saved cursor timestamp. | Readiness now requires a healthy cursor updated within 90 seconds; list metadata uses the cursor’s last successful index time. | `API_READY_DETECTS_STALE_INDEX`; `API_DATABASE_ERRORS_ARE_NOT_EXPOSED_AS_CLIENT_ERRORS`. |
| `/status` | Understand worker and indexer freshness | The freshness label always showed the current time even if the latest indexed event was old. | The page passed `new Date()` to its freshness component. | It now derives freshness from worker heartbeat and cursor timestamps. | Production build and page source review. |
| `/docs/[...slug]` | Open a documentation page | An unknown docs slug rendered an in-app not-found message with an HTTP 200 response. | The catch-all page rendered a fallback instead of invoking Next.js `notFound()`. | Unknown documentation slugs now use the framework 404 response. | Production route check for valid and invalid documentation paths. |
| Public metadata and `/providers` | Share or find public product pages | Public pages shared generic metadata; `/providers` was accidentally blocked by the `/provider` robots prefix. | Metadata existed only at the root and robots rules used a prefix that matched both routes. | Added page-specific descriptions, canonical URLs, Open Graph/Twitter cards and image, a sitemap covering all docs routes, a favicon, and noindex metadata for private workspaces. Robots now blocks `/provider/` while allowing `/providers`. | Production HTML, robots, sitemap, icon and social-image checks. |

## First-time and task-based review

- Browsing does not require a wallet; the landing page links to the public explorer and docs.
- The first viewport states the Provider capital, Pact, Coverage, evidence, GenLayer, and contract roles.
- Pact terms now separate the clauses that apply from those that do not.
- Coverage dates and claim deadline are visible on the Coverage detail page; the deadline is computed from the indexed end time plus the frozen Pact claim window.
- Incident stages distinguish observation, evidence, canonical facts, challenge, and finalization. Pact evaluation and payout remain contract responsibilities.
- Incident lists show observation dates instead of raw Unix seconds; detail pages link the related Claims and their recorded payout.
- Evidence shows onchain provenance, supporting or excluded IDs, submitted hashes, and whether the app checked source bytes. External URIs remain explicitly unchecked by the index.
- Provider total, allocated, reserved, and pending balances are visible on indexed Provider profiles. Reserved capital is described as backing needed by active Coverage and Claims.
- Empty, loading, and API error states exist on the public read routes. Unknown docs slugs now return 404; the app has a root error boundary.

## Visual and accessibility review

- The animated fake telemetry panel was removed. The landing visual now follows FaultPact’s actual lifecycle and has no infinite hero motion.
- Body copy uses the existing system font stack at 15px with 1.5 line height. Key values, table headers, labels, statuses, and review copy were raised where they carried financial meaning. No remote font dependency was added.
- Visible focus, semantic links/buttons, mobile navigation, and reduced-motion styles are present. A keyboard skip link moves focus to the page content.
- Screenshots use the actual production site, not mock product data. Generated marketing art was not added.

## Remaining user-visible gaps

Provider registration, Service creation, Pact drafting/publication, capital writes, customer Claim filing, claimable-credit withdrawal, and a real wallet confirmation/finalization pass are not complete in the web product. These gaps prevent a first-time Provider from completing the requested job and prevent release certification. They are not described as working flows in the UI or this audit.
